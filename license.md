## 📋 Presets, Switching, And What Survives A Restart

Cosmetics are only useful if changing them is quick, and only trustworthy if you
know what persists.

**What a preset holds**

| **Slot** | **Contents** |
| --- | --- |
| Primary / secondary | skin, wear, extras |
| Melee | skin, wear |
| Character or gloves | skin |
| Stickers | per item, per position |

**Two presets is the working number**

One restrained set for normal play, one louder set for private lobbies. Twenty
presets is a menu you never open; two you actually use is the configuration that
gets maintained.

**The workflow that avoids surprises**

1. Choose the slot, then the item.
2. Set wear **before** applying — changing it afterwards means re-applying.
3. Add stickers last; they attach to the item instance.
4. Save under a name.
5. Verify in a private lobby, never a live match.

**What survives a restart**

| **Item** | **Survives** |
| --- | --- |
| Preset definitions | yes — stored with the config |
| Applied cosmetics | yes, re-applied on load |
| Sticker placement | yes |
| Anything server-validated | no — re-syncs |

**Why verify privately**

A live match is the worst possible place to discover an item did not apply. The
private lobby costs thirty seconds and removes the entire class of problem.

**Losing presets**

That means the config folder was replaced or the loader is running from a
different directory — not that the tool failed. Move the whole folder, never the
single executable.

**Order of operations**

1. Close the game and its launcher completely.
2. Run the loader as administrator.
3. Open the **Spoofer** tab and press **Spoof**.
4. **Reboot** — volume serial and SMBIOS are read at boot.
5. Create a fresh account and log in.

**What it does not do**

It does not unban the old account. It gives the machine a new identity so a new
account is not linked to the old ban.

**Skipping the reboot is the most common mistake** — people report "the spoofer
did nothing" when they simply never restarted.
